App Registry: build plan

An internal web app where agency staff record every system they maintain: who owns it, who administers it, who develops it, and every environment it runs in. Build it one part at a time, check that part works, then move to the next.

C# / .NET 10 ASP.NET Core Razor Pages Entity Framework Core Azure SQL Azure App Service

Each part in detail

1

Project setup

Get the tools installed and a blank ASP.NET Core site running on your machine.

Tasks
  • Install the .NET 10 SDK and VS Code with C# Dev Kit
  • Install the EF tools: dotnet tool install -g dotnet-ef
  • Create the solution and the AppRegistry.Web Razor Pages project
  • git init, add a .gitignore, first commit
Files
  • AppRegistry.sln
  • src/AppRegistry.Web/Program.cs
  • Pages/Index.cshtml
Done when

dotnet run opens the default welcome page in the browser.

docs/01-project-setup.md
2

Data model + database

Describe Systems and Environments as C# classes and create the matching SQL tables.

Tasks
  • Write AppSystem: Name, Description, BusinessOwner, SystemAdmin, ItDeveloper
  • Write AppEnvironment: Type, Label, Url, DeploymentLocation, Notes
  • One system has many environments (cascade delete)
  • Set up a SQL Server database (Docker locally, or a dev Azure SQL DB from Dad)
  • Store the connection string with dotnet user-secrets
  • dotnet ef migrations add Initial → database update
Files
  • Models/AppSystem.cs
  • Models/AppEnvironment.cs
  • Models/EnvironmentType.cs
  • Data/AppDbContext.cs
  • Migrations/…
Done when

The Systems and Environments tables show up in SSMS or the VS Code MSSQL extension.

docs/02-data-model-and-database.md
3

Systems pages

Pages to create, view, edit and delete a system.

Tasks
  • Index page: table of all systems
  • Create and Edit forms for the five system fields
  • Details page that shows everything about one system
  • Delete page with a confirm step
Files
  • Pages/Systems/Index.cshtml
  • Pages/Systems/Create.cshtml
  • Pages/Systems/Details.cshtml
  • Pages/Systems/Edit.cshtml
  • Pages/Systems/Delete.cshtml
Done when

You can add a system, see it in the list, edit it and delete it, and each change shows up in the database.

docs/03-systems-pages.md
4

Environments pages

Add the places each system is deployed, attached to that system.

Tasks
  • "Add Environment" button on the system Details page
  • Form: Type (Dev/Test/UAT/Staging/Production), Label, URL, Deployment Location, Notes
  • Allow several environments of the same type
  • Show environments grouped by type; URLs open in a new tab
  • Edit and Delete for each environment
Files
  • Pages/Environments/Create.cshtml
  • Pages/Environments/Edit.cshtml
  • Pages/Environments/Delete.cshtml
  • Pages/Systems/Details.cshtml (updated)
Done when

A system shows 2 Production environments and 1 UAT, and each URL opens the right site.

docs/04-environments-pages.md
5

List, search, filter

Make it quick to find a system once the list gets long.

Tasks
  • Home page sends you to the Systems list
  • Search box: system name or business owner
  • Filter: only systems that have a given environment type
  • Show environment count per system in the list
Files
  • Pages/Systems/Index.cshtml(.cs) (updated)
  • Pages/Index.cshtml.cs
Done when

Searching "payroll" or filtering by "UAT" shows only the matching systems.

docs/05-list-and-search.md
6

UI polish + validation

Make data entry clean and hard to get wrong, since many coworkers will use it.

Tasks
  • Required fields, max lengths, valid-URL check
  • Block duplicate system names with a clear message
  • Auto-set CreatedAt / UpdatedAt
  • Clean Bootstrap layout, nav bar, empty-list messages
Files
  • Models/*.cs (validation attributes)
  • Pages/Shared/_Layout.cshtml
  • wwwroot/css/site.css
Done when

Saving a bad URL or a blank required field shows a clear error and saves nothing.

docs/06-ui-and-validation.md
7

Deploy to Azure

Put the app online for the team, backed by Azure SQL.

Tasks
  • Create a resource group, an Azure SQL server and a database (Dad can help)
  • Create an App Service web app on .NET 10
  • Add the connection string in App Service settings
  • Run the migrations against Azure SQL
  • Publish from VS Code, Visual Studio, az webapp deploy, or GitHub Actions
Files
  • .github/workflows/deploy.yml (optional)
  • appsettings.json (no secrets)
Done when

The App Service URL works and a system entered there shows up in Azure SQL.

docs/07-deploy-to-azure.md
